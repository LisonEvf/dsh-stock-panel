/*
 * ============================================================================
 * A股量化工作台 · 宽视图沉浸式盯盘台样式（v1.3）
 * ============================================================================
 *
 * 本文件是插件唯一的样式源（Tailwind 指令 + 自绘组件类），由
 * scripts/build-client.mjs 的 css-as-string 插件在构建期编译成 CSS 字符串，
 * client 半把它注入 <head>（id=dsh-stock-panel-css）。
 *
 * ## 主题：跟随 DSH（不写死浅色）
 *
 * 宿主 ui-layout 的主题呈现器会把解析后的 design token 写到 body 上
 * （`--dsw-alias-*` / `--dsw-static-*`），并维护 `body[data-ds-dark-theme]`。
 * 本文件只做一层**语义映射** `--dc-*` → `--dsw-*`，所有组件类只消费 `--dc-*`，
 * 于是明暗主题自动跟随，无需页面感知。
 *
 * 唯一的自持配色是 A 股语义色（红涨绿跌），与 K 线组件（components/KlineChart.tsx
 * 的 UP/DOWN 常量）保持一致：暗色下换成更亮的同色系，避免暗底发闷。
 *
 * ## 布局：三段式
 *
 *   .dc-shell ← 纵向：状态带 / 主体 / 底栏
 *   .dc-strip     常驻状态带（时段·情绪·指数·广度·AI 入口·搜索）
 *   .dc-body  ← 横向：左栏列表 | 主区 | 右栏 AI
 *   .dc-rail--left / .dc-main / .dc-rail--right
 *
 * 左右栏的显隐由 shell 的 data 属性控制（窄屏默认收起），不靠媒体查询硬切，
 * 以便用户手动展开成浮层。
 */

/* 状态带：常驻，任何视图都不变。
 *
 * 布局用 **grid 而不是 flex**（B1，实测驱动）：
 *   flex 版本只有"指数条"那一段可伸缩，右簇 flex:none 不能收缩，一旦内容变多

/*
 * 列流排版：把「顺序流程」的各步骤在宽屏并排展开，窄屏自动回落单列。
 *
 * 用 CSS multi-column 而不是 grid：流程块高度差异大，grid 按行对齐会留下大片空白，
 * 多列则是紧密接排（接近瀑布流），更像"看板"。
 * 每块 break-inside: avoid，防止卡片被从中间劈开。
 *
 * 列数按**主区容器实测宽度**（AppShell 量 `.dc-main` 后给 dc-main--flow2/3 类），
 * 不是视口 —— 原先用 @media (min-width:900/1340px) 判定，左右栏都开时
 * 主区可能只有 600px 却仍排 3 列（每列 ~190px，实测挤成一团）。
 */
/* 列流：**行优先的 grid**，不是 CSS 多列（`columns`）。
 *
 * 为什么换掉 `columns`：多列是"先填满第一列再填第二列"，于是编号顺序在视觉上变成
 *   ① ④ ⑥ / ② ⑤ ⑦ —— 复盘页的七步是**有严格序号**的流程，读起来就是乱的（用户实测反馈）。
 * grid 是行优先：① ② ③ / ④ ⑤ ⑥ / ⑦，与引导条的 ①›②›③… 一致，且 DOM 顺序 = 视觉顺序
 * （键盘 Tab / 读屏顺序也跟着对）。
 *
 * 列数按**主区容器实测宽度**分档（不是视口；左右栏都开时主区可能只有 600px）：
 *   ≥1450 → 4 列 · ≥1100 → 3 列 · ≥780 → 2 列 · 否则 1 列。
 * 阈值刻意放低到 1100（原 1180）：实测在 2048 宽的窗口下主区只有 ~1148px，
 * 原阈值让宽屏用户只拿到 2 列 —— "再分一栏"的最直接收益。 */

/* ─────────────────────────── 8. 作用域 reset（= preflight 的作用域版本） ───────────────────────────
 *
 * 背景：Tailwind 的 preflight 是**全局**的，而本插件的 CSS 被注入宿主 `<head>`，
 * 于是 preflight 会同时作用于 DSH shell 的 DOM（`*{border-width:0}`、
 * `button{background:transparent}`…）。宿主不使用 Tailwind（组件样式是 CSS Modules，
 * 见官方 web-styling 规范），这不是它该承受的东西。
 *
 * 所以：`tailwind.config.js` 关掉 preflight（corePlugins.preflight = false），
 * 在这里**按作用域补回同一批规则**（只作用于 `.dsh-stock` 内），
 * 从而做到「宿主不再被污染」且「插件自身渲染与以前一致」。
 *
 * 两条纪律：
 *   1. 一律用 `:where()` 把特异性压到 0（preflight 用 `*`，特异性也是 0）——
 *      否则会压过 Tailwind 工具类（`.border` 只设 border-width，靠 preflight 的
 *      `border-style: solid` 生效；`.box-content` 同理）；
 *   2. 只补 preflight 里**会影响插件**的那些元素规则，html/body 级别的全局规则不补
 *      （宿主自带 `html,body,#root{height:100%;margin:0}`，实测确认）。
 */

/* 通用：与 preflight 的 `*, ::before, ::after` 等价（border-color 取 preflight 的默认值） */
:where(.dsh-stock, .dsh-stock *, .dsh-stock ::before, .dsh-stock ::after) {
  box-sizing: border-box;
  border-width: 0;
  border-style: solid;
  border-color: #e5e7eb;
}

/* [hidden] 的 display:none 由 preflight 提供；这里补一份同特异性的（0,1,0），
   保证 `.dc-rail[hidden]` 之外的普通 hidden 用法也成立 */
:where(.dsh-stock [hidden]) {
  display: none;
}

:where(.dsh-stock a) {
  color: inherit;
  text-decoration: inherit;
}

/* ⚠️ 下面这组必须整条包在 `:where()` 里（特异性 0）。
 *
 * 踩过的坑（2026-09-12 实测）：最初写成 `:where(.dsh-stock) button,
 * :where(.dsh-stock) [type='button'] …` —— `:where()` 只吃掉了宿主那一段，
 * 剩下的 `[type='button']` 是**属性选择器 = 类级特异性 (0,1,0)**，
 * 与 `.dc-nav-item`（也是 (0,1,0)）打平；而本段在文件末尾 → **后来者赢**，
 * 于是把组件自己的 `padding: 5px 11px` / `border` 全部清零（真机表现为状态带导航
 * 「复盘作战看盘工具」挤成一团）。preflight 当年没这个问题，是因为它在文件最前面。
 * 结论：reset 一律零特异性，把顺序决定权交回组件类。 */
:where(.dsh-stock button, .dsh-stock [type='button'], .dsh-stock [type='reset'], .dsh-stock [type='submit']) {
  font: inherit;
  color: inherit;
  margin: 0;
  padding: 0;
  cursor: pointer;
  background-color: transparent;
  background-image: none;
  border: none;
}

:where(.dsh-stock input, .dsh-stock select, .dsh-stock textarea) {
  font: inherit;
  color: inherit;
  margin: 0;
  padding: 0;
}
:where(.dsh-stock ::placeholder) {
  opacity: 1;
  color: #9ca3af;
}

:where(.dsh-stock ul, .dsh-stock ol) {
  margin: 0;
  padding: 0;
  list-style: none;
}

:where(.dsh-stock h1, .dsh-stock h2, .dsh-stock h3, .dsh-stock h4, .dsh-stock h5, .dsh-stock h6) {
  margin: 0;
  font-size: inherit;
  font-weight: inherit;
}

:where(.dsh-stock p) {
  margin: 0;
}

:where(.dsh-stock table) {
  border-collapse: collapse;
  border-color: inherit;
  text-indent: 0;
}

:where(.dsh-stock img, .dsh-stock video, .dsh-stock canvas) {
  display: block;
  vertical-align: middle;
}

:where(.dsh-stock svg) {
  display: inline-block;
  vertical-align: middle;
}

:where(.dsh-stock hr) {
  height: 0;
  color: inherit;
  border-top-width: 1px;
}

:where(.dsh-stock textarea) {
  resize: vertical;
}

 *   .ds-no-scrollbar — 横向 Tab/条带滚动时不显示滚动条

/* ─────────────── 9. 宿主「会话列外壳」适配（工作台视图专用） ───────────────
 *
 * 本节**不是** `.dsh-stock` 内部的样式，而是对宿主两个元素的选择性改写。
 * 为什么必须放在这里：它们是宿主 `ui-conversation` 画的、**在插件视图之上**的东西，
 * 我们的 DOM 里没有它们，只能靠 CSS 选择器命中（不改宿主文件 —— v1.2 起的纪律）。
 *
 * 一条纪律：**工作台里这两样都不要**（用户决策）。
 *   ① [data-width-handle]  正文栏宽度的两条拖拽条 —— 挡路（见下）；
 *   ② [data-composer-seat] 底部对话输入框 —— 工作台是盯盘台，不占最下面那一条。
 *      要打字切上方「对话」标签（那里输入框原样俱在）；插件自己发出的 prompt 走
 *      `setDraft + submit`，不依赖输入框可见。
 *
 * 作用域由 `lib/host-chrome.ts` 写在 `<body>` 上的 `data-dc-workbench` 标记限定：那个模块在
 * 工作台视图**挂载期间**才打标记，而 ui-conversation 只渲染当前选中的视图条目
 * （`only: active.id`）—— 所以「对话」标签页完全不受本节影响（挂载 ⟺ 选中）。
 *
 * 依赖的宿主钩子（只观察、不改写；DSH 哪天改名 → 退化为"什么都没隐藏"，不报错；
 * `window.__STOCK_PANEL__.chrome()` 会把实况报出来）。
 *
 * 特异性说明（刻意不用 `!important`）：本节选择器是 (0,2,1)，宿主的
 * `.wSkVaW_widthHandle` / `.wSkVaW_composerSeat` 是 (0,1,0)，赢在特异性上、不靠顺序
 * （本文件在宿主样式之后注入这一点也不依赖）。
 */

/* ① 移除正文栏宽度拖拽条（两条贯穿全屏高度的 col-resize 热区）
 *
 * 实测（DSH dsh-client-ui-conversation）：
 *   `.wSkVaW_widthHandle{ position:absolute; top:0; bottom:0; z-index:8;
 *                         cursor:col-resize; width:min(40px, calc((100% - 正文宽)/2 - 48px)) }`
 *   `[data-side=left]{right:calc(50% + 正文宽/2 + 24px)}` · `[data-side=right]{left:…}`
 *
 * 它的用途是"拖居中**正文栏**的宽度"（对称写 `--dsh-chat-user-width`），位置在正文列
 * 两侧的留白里 —— 「对话」页里落在正文外的空白上，合理。但工作台是**满宽**面板，
 * 于是这两条 40px 的带子压在面板左右边缘，而且 `top:0;bottom:0` 一路通到**底部对话框两端**：
 * 点按钮、点列表行、拖选文字都会被它接管（光标变 col-resize）。
 *
 * 藏掉不损失任何能力：工作台里没有正文栏，那条宽度偏好（`dsh.conversation.contentWidth`）
 * 是「对话」页的东西 —— 回「对话」标签页照样拖，本节不生效。
 * 宿主自己在"composer 悬浮"场景也是这么处置这两条的（`.wSkVaW_root:has([data-conversation-composer-overlay])
 * .wSkVaW_widthHandle{display:none}`），这里沿用同一手法。 */
body[data-dc-workbench] [data-width-handle] {
  display: none;
}

/* ② 移除底部对话输入框（座位整块让给主区）
 *
 * 座位 `display:none`（**不卸载**：Lexical 编辑器实例还在，插件的「深入对话」注入照旧能发）。
 * 宿主的 `viewArea` 是 `flex:1 1 0; min-height:0`，座位一让位，主区就吃满整列高度
 * （面板高度由 AppShell 按容器实测封顶，会跟着重算）。
 * 只在本视图内生效：切回「对话」标记随卸载摘掉，输入框原样回来。 */
body[data-dc-workbench] [data-composer-seat] {
  display: none;
}
